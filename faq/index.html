01 端口 3080 被占用 / 页面打不开怎么办？ 高频

换一个空闲端口启动，或先停掉占用 3080 的旧进程，再打开终端打印的新地址。

原因

另一个 DSH 实例或其他服务占用了 3080；也可能你把端口换成了 3081，却仍在打开旧地址。监听失败会让启动进程报告失败的 fiber，而不是自动换端口。

处理步骤
  1. 在 Windows 上查 3080 的监听进程，确认 PID 归属后再决定是否结束
  2. 用 --port 指定其他端口重新启动，并打开终端新打印的 URL
  3. 如果改过 --host，确认访问的地址与绑定地址一致
  4. 仍不通时检查本机防火墙与代理设置，不要只怀疑 DSH
命令
powershell
Get-NetTCPConnection -LocalPort 3080 -State Listen | Select-Object LocalAddress, LocalPort, OwningProcess
sh
npx @deepseek-ai/dsh web --no-open --port 3081

02 模型报 MISSING_CREDENTIAL 或 401，密钥应该配在哪？ 高频

在 设置 → 模型 中保存对应提供商的密钥；保存后下一次请求生效，不需要重启。

原因

密钥没有保存、保存到了错误的提供商，或环境变量后备没有被检测到；也可能是密钥被撤销、额度耗尽，或自定义端点的地址与协议不匹配。

处理步骤
  1. 打开 设置 → 模型，在 DeepSeek 卡片输入密钥并保存
  2. 第三方提供商先选提供商 id，再填它自己的密钥
  3. 自定义端点核对基础 URL、API 协议和模型列表，协议只能选网关实际使用的一种
  4. 用 获取可用模型 验证；失败就手动填模型 ID，探测只是便利手段
  5. 确认凭据文件存在且当前用户可读，不要把密钥贴进仓库或聊天记录
命令
powershell
Test-Path "$env:USERPROFILE\.dsh\.credentials.yaml"
sh
npx @deepseek-ai/dsh web

03 启动提示 Node 版本不满足，或 npx 直接失败？

当前 0.2.2-rc.1 的 dsh 包声明 Node >= 24.9.0，先升级 Node 并重开终端。

原因

系统 Node 太旧；多版本管理器切换到了旧版本；IDE 内置终端与系统终端使用的 Node 不是同一个。

处理步骤
  1. 用 node -v 确认实际版本，满足 >= 24.9.0 再启动
  2. 用 nvm-windows 或 fnm 安装并切换到 24.9.0 以上版本
  3. 重开终端，确认 which node 与 npm 指向同一套安装
  4. 清理 npx 缓存后重试，避免命中旧的 dsh 包
命令
powershell
node -v
npm -v
powershell
nvm install 24.9.0
nvm use 24.9.0
node -v

04 插件装不上，或装了却没有生效？

用 dsh plugin --profile <name> add 安装声明了 dsh.bundle 的组合包，并用同一个 profile 启动。

原因

包没有声明 dsh.bundle；装进了另一个 profile；engines.dsh 或 peer 依赖不满足；从 git 安装时没有构建产物或未授权 prepare 脚本。

处理步骤
  1. 检查包内 package.json 是否有 dsh.bundle.patch
  2. 确认安装与启动使用同一个 profile，例如都用 --profile web
  3. 用 --dump-config 确认组合包里出现该层
  4. git 安装失败时按提示把包键写进该 profile 的 pnpm-workspace.yaml allowBuilds，再重试
  5. 不想让用户授权构建就改用 npm 预构建包或 tarball
命令
sh
dsh plugin --profile web add dsh-hello-plugin
sh
dsh --profile web --dump-config

05 命令报文件写入被拒 / sandbox denied，怎么办？ 高频

当前沙箱模式不允许写这个路径；把目标移到工作区内，或在明确风险后走一次性提权。

原因

read-only 模式只允许必要接收器；workspace-write 只允许会话工作区根与后端承诺的临时区域；会话 cwd 可能不是你以为什么目录。Windows ACL runner 还可能在硬链接等边界上只做到部分强制执行。

处理步骤
  1. 先用 Get-Location 确认会话工作区，再把输出改到工作区内
  2. 构建、安装依赖这类需要写盘的任务切到 workspace-write
  3. 确实要越界时，让工具调用带 sandbox_permissions 与 justification 发起一次性重试，并完成审批
  4. 不要把整个会话长期切成 danger-full-access 来绕过问题
  5. sandbox unavailable 说明没有可用后端，属于环境故障，不是命令写错
命令
powershell
Get-Location
Set-Content .\sandbox-probe.txt ok
Get-Content .\sandbox-probe.txt
sh
pwd
标签
权限沙箱
官方文档：沙箱 官方文档：权限预设 官方文档：审批
06 操作一直被拒绝，或审批弹窗根本不出现？

ask 策略下只有 allowed-once 会放行；never 策略或没有可用应答者时，请求一律失败关闭。

原因

会话权限预设是 danger-full-access + never；Web UI 不在前台或连接断开，没有应答者；请求被取消或超时；被委派的子代理使用固定的 never 策略。

处理步骤
  1. 检查 Permissions 选择器当前是哪个预设
  2. 交互开发切到 workspace-write（workspace-write + ask）
  3. 在前台确认审批弹窗并选择允许一次
  4. 无人值守场景不要依赖审批，改设计成只读或预授权操作
  5. 被拒绝后重新发起操作，旧请求不会复活
命令
text
# 审批是 Web UI 交互，没有对应的 dsh 子命令
# 在会话顶部的 Permissions 选择器中切换预设

07 上下文快满了、模型开始忘事，怎么压缩？ 高频

空闲时输入 /compact 手动压缩，或让自动压缩在压力或溢出时接管；压缩只替换模型可见的旧历史，日志不丢。

原因

长会话累积了大量工具输出；自动压缩阈值还没到，或单个超大结果无法通过压缩修复；会话正在跑轮次或已有压缩在运行。

处理步骤
  1. 等当前轮次结束再执行 /compact，它只在空闲时可用
  2. 压缩后重新确认关键约束，摘要不保证保留每个细节
  3. 把无关任务拆到新会话，别让一个会话承担所有历史
  4. 重跑大输出命令时限制输出，或写入文件只读关键片段
  5. /compact 不接受参数，也不要指望它压缩单个超大工具结果
命令
text
# 在 DSH 会话输入框执行（不是 shell）
/compact
标签

08 PowerShell 在沙箱里报「仅核心类型」或 cmdlet 不可用？

只读沙箱下 PowerShell 可能以 ConstrainedLanguage 运行，.NET 静态调用、Add-Type、COM 会被拒绝；改用 cmdlet 或切到 workspace-write。

原因

沙箱策略限制了 PowerShell 语言模式；这是策略拒绝，不是命令语法错误。只读模式还会拒绝任何写入，即使语言模式允许。

处理步骤
  1. 优先用 Get-ChildItem、Get-Content、Select-String 等 cmdlet 完成同样的事
  2. 需要 .NET 或写盘时切到 workspace-write，并确认操作发生在工作区内
  3. 不要反复换写法试图绕过策略；被拒绝是预期边界
  4. 必须用完整 .NET 能力时，由人手动在沙箱外执行
命令
powershell
Get-ChildItem -File | Select-Object -First 10
powershell
Get-Content .\package.json -Raw

09 反向代理之后页面能开，但所有 API 都返回 403？ 高频

浏览器使用的 authority 没有被 --trusted-host 接纳；补上它，并让代理保留原始 Host。

原因

栅栏只接受 loopback、监听器自身绑定地址和 --trusted-host 点名的 authority；--public-url 只是公告，不授予信任。代理改写 Host 也会导致 403。

处理步骤
  1. 用 --trusted-host 点名浏览器可见的 authority，可带端口
  2. 让代理原样转发浏览器可见的 Host，不要改写成监听器地址
  3. 确保代理剥离挂载前缀，/ui/api/... 以 /api/... 抵达监听器
  4. 转发 Upgrade 与 Connection 头，保证 WebSocket 能升级
  5. 把 cookie 的 Path 改写到挂载前缀，HTTPS 链路上加 Secure
命令
sh
dsh --profile web --public-url https://app.example/ui/ --trusted-host app.example
sh
curl.exe -I https://app.example/ui/

10 定时任务按什么时区触发？为什么没在预期时间跑？

每日和每周规则按保存的 IANA 时区与本地钟点触发；宿主没运行就不会投递。

原因

保存的时区与预期不符；自然语言请求使用的是浏览器时区；宿主关闭期间调度停止；不存在的本地时间会被跳过；一次性任务只保存 UTC 时点。

处理步骤
  1. 创建时显式写时区，例如 每天 Asia/Shanghai 09:00
  2. 在自动化任务页面核对频率、时区与下次运行时间
  3. 需要准点就保持宿主常驻，或把关键调度放到外部调度器
  4. 跨夏令时使用 IANA 时区，不要用固定偏移
  5. 重启后重复任务只补最近错过的一次，别期待补齐全部
命令
text
# 在对话中创建（示例）
每天 Asia/Shanghai 09:00 汇总昨天的 CI 失败并给出修复建议

11 安装插件提示 DSH 版本不兼容？

插件的 engines.dsh 或 dsh peer 依赖与当前 0.2.2-rc.1 不匹配；装兼容版本或升级 DSH，不要靠版本豁免硬上。

原因

插件要求更高或更低的 DSH 版本；开发者预览阶段破坏性变更频繁；版本豁免会跳过检查，但运行时仍可能崩溃。

处理步骤
  1. 用 dsh --version 确认当前版本
  2. 查看插件 package.json 的 engines.dsh 或 @deepseek-ai/dsh* peer 范围
  3. 选一个满足范围的插件版本，或升级 DSH 到插件要求的版本
  4. 确需豁免时只在隔离环境试用，并明确可能崩溃或丢数据
  5. 把可用版本写进项目文档，避免团队成员各自装不同版本
命令
sh
dsh --version
sh
npm view dsh-hello-plugin engines --json

12 写了 SKILL.md，但模型看不到或不调用？

检查目录位置、kebab-case 名称和 description；嵌套的 SKILL.md 不会被发现。

原因

放错根目录或嵌套过深；名称不是 kebab-case；description 太泛；设置了 disable-model-invocation；项目根不是你以为的目录。

处理步骤
  1. 放到 <project>/.dsh/skills/<name>/SKILL.md 或用户技能根 <dshHome>/skills/<name>/SKILL.md
  2. 名称只用小写字母、数字和连字符
  3. description 写清触发场景与任务类型，不要写口号
  4. 确认 frontmatter 以 --- 开头和结束，YAML 缩进正确
  5. 项目根是最近的 .git 祖先；找不到时用当前 cwd，必要时新开会话让目录刷新
命令
powershell
New-Item -ItemType Directory -Force .dsh\skills\weekly-report
powershell
Get-Content .dsh\skills\weekly-report\SKILL.md -TotalCount 10

13 长命令跑到一半被杀，或提示超时？

前台命令有超时上限；把长任务放后台运行，或显式提高 timeoutMs。

原因

执行器按 timeoutMs 杀掉超时命令，实现还会给它设上限；输出超过捕获预算时只保留尾部；会话取消也会终止命令。

处理步骤
  1. 用 run_in_background 启动长任务，再用 job_output 轮询，不要在前台干等
  2. 给足 timeoutMs，并知道实现可能封顶
  3. 把输出重定向到文件，只读尾部做判断
  4. 把大任务拆成可增量验证的步骤，避免一次跑几十分钟
  5. 不要用 sleep 轮询，后台任务完成会通知
命令
powershell
pnpm run build *> build.log
powershell
Get-Content .\build.log -Tail 50 -Wait

14 API 密钥存在哪里？怎么备份或迁移？

在 $DSH_HOME/.credentials.yaml，Windows 默认 C:\Users\<you>\.dsh\.credentials.yaml；settings 只保存对它的引用。

原因

凭据由本地 provider 管理，DSH_HOME 可以被环境变量改写；settings 与 cordis.yml 里只有引用，没有明文值。

处理步骤
  1. 先确认 DSH_HOME 实际指向哪里
  2. 备份 .credentials.yaml 到受控的加密位置，并限制文件权限
  3. 迁移时只复制该文件，不要把整个 .dsh 提交到仓库
  4. 轮换密钥后在 设置 → 模型 重新保存，下一次请求即生效
  5. 环境变量后备仍然可用，但显式保存的值优先
命令
powershell
$env:DSH_HOME
powershell
Get-Item "$env:USERPROFILE\.dsh\.credentials.yaml" | Select-Object FullName, Length, LastWriteTime
