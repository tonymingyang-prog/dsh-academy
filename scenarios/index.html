Scenarios

把能力装进真实流程

六个可以直接复用的场景：每个都写明业务目标、技术栈、执行步骤与最终交付物。第一个场景就是这座教学站自己的自动更新流水线。

SCENARIO 01 实战

每 3 天自动巡检并更新教学站

每 3 天检查教学站的死链与构建状态，发现问题就修复并重新部署。

DSH ScheduleNode.jsGitHub Actions

执行步骤

  1. 00把巡检与构建写成可重复执行的 npm 脚本，先在本地跑通，确保退出码能表达成功或失败。
  2. 00用 /goal 定义验收标准：死链为 0、构建通过、部署后首页返回 200。
  3. 00让模型创建定时任务，明确频率与 IANA 时区，例如 每 3 天 Asia/Shanghai 09:00。
  4. 00任务运行时先只读巡检，发现死链再改内容；写操作仍受工作区沙箱约束。
  5. 00宿主需要常驻才能按时投递；不想常驻就改由 GitHub Actions 的 cron 触发同一套脚本。
sh
npm run check:links
npm run build
sh
dsh --profile web --no-open
每 3 天自动得到一份巡检结论；有死链或构建失败时被修复并重新部署，没有问题时只留一条简短记录。
SCENARIO 02 进阶

用目标驱动跨文件重构

在不改变公开 API 的前提下，把认证模块拆成可测试的小单元并补齐测试。

DSH GoalTypeScriptVitest

执行步骤

  1. 00先跑基线：记录现有测试结果与公开导出，作为重构不能破坏的边界。
  2. 00用 /goal 写清目标、验收命令和禁止事项，例如 不新增运行时依赖。
  3. 00第一轮只让 agent 输出拆分方案与影响面，不改代码；确认后再进入实现。
  4. 00每轮结束检查 diff 与测试结果，发现方向偏了就 /goal edit 修正目标。
  5. 00需要人工评审时 /goal pause 暂停自动续跑，恢复后 /goal resume 继续。
  6. 00目标完成后让 agent 标记完成；不要用 /goal clear 代替验收。
text
/goal 拆分认证模块并补齐测试，保持公开 API 不变，pnpm test 全绿
sh
pnpm test
pnpm run build
text
/goal
/goal pause
重构分多轮推进，每轮都有测试与 diff 证据；目标完成时公开 API 未变，测试覆盖新增单元。
SCENARIO 03 实战

工作流并行审计整个 monorepo

对仓库内所有包做依赖、许可证与过时 API 的只读审计，产出去重后的风险清单。

DSH WorkflowSubagentpnpm

执行步骤

  1. 00先用一条命令列出所有包名，作为工作流的 args 输入。
  2. 00写工作流脚本：按包并行启动只读审计子代理，每个子代理返回结构化结论。
  3. 00用 phase 标记阶段、log 汇报进度，让长任务在 UI 里可观察。
  4. 00汇总时过滤 null、按风险等级排序、合并重复问题，再抽样核对证据。
  5. 00用 maxTotalAgents 限制并发规模，先拿 3 个包试跑再全量。
sh
pnpm -r list --depth -1
js
phase('audit')
const reports = await parallel(
  args.packages.map((p) => () =>
    agent(`只读审计 ${p}：依赖风险、许可证、过时 API`, { label: p, phase: 'audit' })
  )
)
return reports.filter(Boolean)
一次运行覆盖全部包，得到按风险排序、带文件证据的清单；失败项单独列出，不伪装成成功。
SCENARIO 04 入门

把周报 SOP 变成技能

让 agent 按团队固定格式生成周报草稿，而不是每次临时发挥。

DSH SkillsMarkdownGit

执行步骤

  1. 00在项目里创建 .dsh/skills/weekly-report/SKILL.md，跟着仓库一起版本化。
  2. 00frontmatter 写 kebab-case 的 name 和具体的 description，正文写输入、步骤、输出格式与验收。
  3. 00把最容易被忽略的规则写进正文，例如 不直接发布、必须列出风险项。
  4. 00新开会话确认技能出现在目录中，让模型执行一次并按反馈修订正文。
  5. 00团队需要统一行为时，把技能提交进仓库；只给用户手动调用时设 disable-model-invocation。
powershell
New-Item -ItemType Directory -Force .dsh\skills\weekly-report
powershell
Get-ChildItem .dsh\skills -Recurse -Filter SKILL.md | Select-Object FullName
任何人在该仓库开新会话都能触发同一套周报流程，输出格式稳定，修改流程只需改 Markdown。
SCENARIO 05 实战

把 DSH Web UI 发布到公网

在自有域名下安全提供 DSH Web UI，外部浏览器可访问且不被 403 拦住。

NginxTLSDSH Web

执行步骤

  1. 00先在本机确认 dsh web 正常，再决定挂载路径，例如 https://app.example/ui/。
  2. 00配置代理：保留 Host、剥离 /ui 前缀、转发 Upgrade 与 Connection、改写 cookie Path。
  3. 00用 --public-url 公告外部地址，用 --trusted-host 点名浏览器使用的 authority。
  4. 00TLS 在代理或监听器上终止；监听器自签终止时传 --tls-cert 与 --tls-key。
  5. 00上线验收：首页 200、API 无 403、WebSocket 正常、HTTPS 下 cookie 带 Secure。
  6. 00把监听端口限制在代理或内网，启动 URL 含 token，只发给预期用户。
sh
dsh --profile web --public-url https://app.example/ui/ --trusted-host app.example
sh
curl.exe -I https://app.example/ui/
sh
nginx -t
团队成员通过 https://app.example/ui/ 正常使用，接口与流式输出都工作，未授权来源仍被栅栏拒绝。
SCENARIO 06 进阶

接一个记忆 MCP，让 agent 记住团队约定

让 DSH 在新会话里召回团队的技术选型与命名约定，而不是每次重复交代。

MCPMemorixDSH

执行步骤

  1. 00选一个记忆服务并安装，例如 Memorix 或 MCP Reference Memory，确认它能独立启动。
  2. 00用 --patch 加载对应的记忆配置 overlay；交付组合默认不包含任何记忆服务器。
  3. 00在会话 A 明确写入一条唯一可验证的记忆，确认写入工具返回成功。
  4. 00在同一个宿主里新开会话 B，不复制会话 A 的对话，要求它检索这条记忆。
  5. 00确认召回后再让它用该偏好完成一个小任务；需要长期生效就把 overlay 合并进 profile 的 patch 层。
sh
npm install --global memorix@1.3.0
sh
dsh web --patch "$PWD/apps/cli/config/examples/mcp-memory/memorix.cordis.yml"
新会话无需重复交代就能召回团队约定；记忆内容由提供方管理，DSH 只负责启动与工具暴露。
