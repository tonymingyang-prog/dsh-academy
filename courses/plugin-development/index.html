插件开发：一切皆插件

写一个能被 Web UI 加载的插件，注册工具、接受配置，再打包成可安装的 bundle。学完你能判断插件为什么没加载、配置为什么没生效。

40 分钟 6 个步骤 实战

学完你能

  • 写最小插件并用 --patch overlay 加载到 Web UI
  • 用 defineTool 注册一个模型可调用的工具
  • 打包成声明 dsh.bundle 的包并安装进 profile
STEP 01

准备源码检出

教程以源码检出的仓库为工作目录：先克隆、安装依赖并构建。pnpm run build 准备产物，pnpm dsh web 直接使用这些产物，不会重新构建。

sh
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
STEP 02

写最小插件并加载

插件就是一个导出 apply(ctx) 的 TypeScript 模块。把它放进临时项目，用只含 insert 的 overlay 指向绝对路径，再启动 Web UI。

ts
import type { Context } from '@deepseek-ai/cordis'
export const name = 'hello-plugin'
export function apply(ctx: Context) {
  console.log('[hello-plugin] plugin loaded!')
}
插件路径必须写绝对路径；patch 只贡献配置，不改变 loader 解析模块路径时使用的 profile 目录。
STEP 03

创建 overlay

在临时项目里写 cordis.yml，把 id 与绝对路径填进去，然后用 --patch 启动。终端打印 [hello-plugin] plugin loaded! 就说明加载成功。

yaml
- insert:
    - id: hello
      name: '/absolute/path/to/deepseek-harness/scratch-plugin/src/my-plugin.ts'
STEP 04

注册一个工具

声明 inject = ['tools'] 让 Cordis 等工具注册表就绪，再用 defineTool 定义参数、输出 schema 与执行逻辑。模型就能在对话里调用这个工具。

ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'
export const name = 'greet-tool'
export const inject = ['tools']
export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'greet',
    description: 'Greet someone by name.',
    parameters: {
      name: { type: 'string', required: true, description: 'The name to greet' },
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args) {
      return `Hello, ${args.name}!`
    },
  }))
}
STEP 05

让插件接受配置

导出 Config 类型和同名 Schemastery schema，默认值写在 schema 里；apply 的第二个参数就是校验后的配置。配置变更会触发插件热替换，旧注册会被自动清理。

ts
import Schema from '@deepseek-ai/schemastery'
export interface Config {
  greeting: string
}
export const Config: Schema<Config> = Schema.object({
  greeting: Schema.string().default('Hello'),
})
STEP 06

打包成组合包并安装

组合包是一个声明 dsh.bundle 的 npm 包，patch 里按包名引用插件。用 dsh plugin 安装进 profile，再启动同一个 profile；--dump-config 可以确认该层已生效。

sh
dsh plugin --profile demo add ./hello-plugin
dsh --profile demo --dump-config
dsh --profile demo
在 package.json 里用 engines.dsh 声明支持的版本范围；不满足时安装会直接拒绝，而不是带病启动。
PITFALLS

常见坑

overlay 加载后没有任何输出检查插件路径是否为绝对路径、文件是否真的被 Node 加载；patch 的相对路径解析基准不是插件文件所在目录。
apply 里 ctx.tools 是 undefined忘了 export const inject = ['tools']；Cordis 只有在声明依赖后才保证对应服务就绪。
改了配置但行为没变patch 会替换目标行的整个 config，而不是深合并；改已有条目时要重述该行需要的每个键。
从 GitHub 安装后插件加载失败git 安装拉的是源码，不会自动构建；作者要提供自包含的 prepare 脚本，用户还要按提示在 pnpm-workspace.yaml 里授权 allowBuilds。

验收清单

  • 最小插件能在启动日志里打印加载信息
  • 模型能成功调用你注册的 greet 工具
  • 配置项有默认值且能通过 cordis.yml 覆盖
  • 组合包声明了 dsh.bundle 并成功装进 profile
  • dsh --profile <name> --dump-config 能看到你的层
