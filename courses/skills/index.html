技能：把 SOP 变成能力

把团队重复执行的流程写成技能，让模型在需要时按需加载，而不是塞进系统提示词。学完你能写出可被正确发现和调用的 SKILL.md。

20 分钟 5 个步骤 进阶

学完你能

  • 按目录约定创建技能并理解本地发现优先级
  • 写出能被模型正确路由的 name 与 description
  • 验证技能被加载，并控制模型或用户是否可调用
STEP 01

选对技能根目录

项目级技能放在 <project>/.dsh/skills，优先级最高；用户级放在 <dshHome>/skills，跨项目可用。项目根是包含 .git 的最近祖先目录，找不到时用当前 cwd。

powershell
New-Item -ItemType Directory -Force .dsh\skills\weekly-report
本地提供方支持目录包 <name>/SKILL.md 和扁平文件 <name>.md；嵌套的 **/SKILL.md 不会被发现。
STEP 02

写 frontmatter 与流程正文

文件名和目录名用 kebab-case。frontmatter 至少写 name 与 description；正文写清输入、步骤、验收和常见坑，正文只在技能被加载时进入上下文。

markdown
---
name: weekly-report
description: 汇总本周提交、CI 失败与待办，生成周报草稿。当用户要求写周报或总结本周进展时使用。
---
# 周报流程
1. 读取本周 git log 与 CI 结果。
2. 按「完成 / 风险 / 下周计划」三段整理。
3. 输出 Markdown 草稿，不直接发布。
STEP 03

控制谁能调用

frontmatter 的 disable-model-invocation 与 user-invocable 默认都为 true。只给模型用时把 user-invocable 设为 false；只给用户手动用时把 disable-model-invocation 设为 true。

markdown
---
name: release-checklist
description: 发布前的检查清单。仅在用户明确要求发布时使用。
user-invocable: false
---
STEP 04

让模型加载并执行

会话目录只注入已排序的 name 和 description，不包含正文与路径；模型判断相关后调用 skill 工具按名称加载完整正文。因此 description 要写触发场景，而不是写口号。

text
skill({ name: 'weekly-report' })
STEP 05

验证与迭代

新开会话，确认可用技能目录里出现你的条目；让模型执行一次，检查它是否按步骤走、是否漏掉验收。只改正文会立即影响后续加载，不会重发目录消息。

powershell
Get-ChildItem .dsh\skills -Recurse -Filter SKILL.md | Select-Object FullName
PITFALLS

常见坑

写了 SKILL.md，但技能目录里没有检查是否嵌套在更深的子目录、目录名是否 kebab-case、是否放在 .dsh/skills 或用户技能根下；项目根按 .git 定位。
技能存在，模型却从不调用description 写得太泛或没有写触发条件；改成具体任务与场景，并确认没有设置 disable-model-invocation。
同名技能行为跟预期不一样项目级技能会覆盖用户级同名项；检查优先级链，删除或重命名低优先级副本。
frontmatter 格式错误导致技能加载失败确认文件以 --- 开头和结束，YAML 缩进正确；name 必须匹配 kebab-case 正则。

验收清单

  • 技能位于 .dsh/skills/<name>/SKILL.md 或用户技能根下
  • name 是 kebab-case，description 写清触发场景
  • 新会话的可用技能目录里能看到该条目
  • 模型能用 skill 工具加载并返回完整正文
  • 知道如何用 frontmatter 关闭模型或用户调用
