LESSON 02 入门

模型与凭据配置

把 DeepSeek 密钥、第三方提供商和 OpenAI 兼容网关接进 DSH，并知道请求被网关拒绝时该改哪个字段。学完你能独立排查 MISSING_CREDENTIAL 与 401。

20 分钟 6 个步骤 入门

学完你能

  • 在 设置 → 模型 中保存 DeepSeek 密钥并选择默认模型
  • 用自定义模型 API 接入中转站或公司网关，正确选择协议
  • 用 compat 开关修复网关拒绝请求的问题
STEP 01

保存 DeepSeek 密钥

打开 设置 → 模型，在 DeepSeek 卡片输入 API 密钥并保存。密钥只写，保存在 $DSH_HOME/.credentials.yaml，settings 只保留对它的引用。

Windows 默认位置是 C:\Users\<you>\.dsh\.credentials.yaml；不要把它提交进仓库。
STEP 02

添加第三方提供商

选择 添加模型提供商，在 第三方模型提供商 中选取 dsh 自带的条目，列表显示的是提供商 id，例如 anthropic、openai、Kimi 的 moonshotai、GLM 的 zai。输入密钥保存即可。

STEP 03

接入自定义模型 API

中转站、公司网关或自建服务器切到 自定义模型 API，填写小写 Provider ID、基础 URL、API 协议、凭据和至少一个模型。一个提供商只使用一种协议；网关同时支持两种协议时建两个提供商。

Provider ID 是永久的，请求、会话、默认模型和凭据引用都用它。要改名只能新建提供商再删旧的。
STEP 04

探测或手动添加模型

在 模型目录 点 获取可用模型，成功就勾选后 添加所选；失败或列表为空时手动填模型 ID，效果一样。内置提供商始终由已安装目录作答，想探测网关实际模型请用自定义提供商。

text
模型目录 → 获取可用模型 → 勾选 → 添加所选
STEP 05

选择模型与推理等级

在模型选择器里选定模型，它同时成为新会话的默认值；已发送过请求的会话保留自己日志里的模型。声明了推理等级的模型还会出现 推理等级 菜单。

如果默认值指向已删除的提供商，输入框会要求先重新选择模型。
STEP 06

修复网关兼容性

密钥和地址都对、网关却拒绝每个请求时，多半是请求形状不同：推理模型的系统提示词以 developer 角色发出，输出上限写作 max_completion_tokens。在 $DSH_HOME/profiles/web/cordis.patch.yml 的路由上改 compat。

yaml
- id: llm-pi-ai
  config:
    providers:
      my-gateway:
        apiKeyEnv: GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://gateway.example/v1
        compat:
          supportsDeveloperRole: false
          maxTokensField: max_tokens
        models:
          - id: my-model
适配器在下一次请求时重新读取这份文件，不需要重启。patch 会替换整条 config，改已有条目时要保留其他字段。
PITFALLS

常见坑

会话报 MISSING_CREDENTIAL到 设置 → 模型 保存对应提供商的密钥，或提供被引用的环境变量。保存后下一次请求即生效。
获取可用模型返回 401检查密钥本身；模型发现调用的是 OpenAI 兼容的 GET /models，不提供该端点的服务直接手动输入模型 ID。
密钥与地址都正确，网关仍拒绝每个请求先在路由上设 compat.supportsDeveloperRole: false 与 compat.maxTokensField: max_tokens，再逐个模型收窄。
自定义提供商保存后模型仍然不可用确认协议与网关实际使用的协议一致，基础 URL 带对路径前缀，并且模型列表非空。

验收清单

  • 设置 → 模型 中至少一个提供商显示已配置
  • 能成功发送一次模型请求，没有 401 或 MISSING_CREDENTIAL
  • 自定义提供商填了 Provider ID、地址、协议和至少一个模型
  • 知道 compat 开关写在哪份 cordis.patch.yml 里
  • 密钥只存在于凭据文件或环境变量，没有写进仓库
